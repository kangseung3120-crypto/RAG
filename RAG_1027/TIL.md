## 한 줄 요약

 RAG를 **같은 기준으로 재는 법**을,  그 측정으로 찾은 **빈틈을 종류별로 메우는 법**을 배웠다. 핵심 태도는 확장을 붙이기 전에 "정보가 어느 단계에서 처음 사라졌나"부터 찾는 것이다.

## 평가: 같은 기준으로 재기

| 교안 | 배운 것 | 기억할 예시 |
| --- | --- | --- |
| 8-1 Golden Dataset | 질문마다 참고 답변 · 근거 문서 ID · 답 가능 여부 · dev/test를 정해 둔다. 모델 출력을 정답으로 복사하지 않는다. | q06 출장비 = 숙박 1박 12만원 + 식비 1일 3만원, **합산 불가**. "15만원"은 오답 |
| 8-2 Hit · Recall | Hit@k는 하나라도 찾으면 1, Recall@k는 필요한 문서 중 찾은 비율. 평균보다 질문별 점수를 본다. | q06 k=1 → Hit 1 / Recall 0.5. dev 평균 0.9는 q10 하나가 0점 |
| 8-3 RAGAS | 근거에 맞나(Faithfulness)와 질문에 답했나(Relevancy)는 다른 축이다. | A 1.0 · B 0.5(30만원 오류) · C 1.0이지만 질문과 무관 |
| 8-4 전후 비교 | 나머지는 고정하고 하나만 바꾼다. dev로 고르고 test는 확인만. | BM25 0.9 → Dense · Hybrid 1.0, 상승분은 q10 하나 |

- 답이 없는 질문의 정답은 "아니요"가 아니라 **"현재 자료에서 확인할 수 없어요"**.
- 검색은 청크 단위, 정답 비교는 문서 ID 단위. 청크 k개를 먼저 자른 뒤 문서로 바꾼다.
- 질문 20개짜리 결과를 "서비스 성공률 100%"로 부풀리지 않는다.

## 확장: 빈틈에 맞는 도구 고르기

| 빈틈 | 확장 | 배운 것 |
| --- | --- | --- |
| 문장 중간에 조건이 잘림 | 9-1 Parent-Child · Compression | 작은 Child(80자)로 찾고, 답변엔 Parent(원문 148자)를 넘긴다. 압축할 때 승인 조건처럼 **답을 바꾸는 조건**이 남았는지가 기준 |
| 질문 표현 때문에 못 찾음 | 9-2 Corrective / Agentic RAG | 결과를 보고 다시 검색한다. 핵심은 **언제 멈출지**: candidates\_ready · repeated\_query · search\_limit. 인용이 Context에 없으면 답변 차단 |
| 여러 규정의 관계를 따라가야 함 | 9-3 GraphRAG | 규정 → 제출물 · 승인자를 간선으로, 간선에 조건과 출처 저장. Local · Global · DRIFT 검색 방식 구분 |
| 표 · 이미지가 답에 중요 | 9-4 Multimodal · ColPali | 숫자는 **값 + 단위 + 출처**로 저장. ColPali는 페이지를 이미지로 검색, MaxSim으로 점수 |

- 70자로 압축하면 승인 조건이 빠져 "13만원 숙박은 정산 불가"로 잘못 단정한다.
- candidates\_ready는 "검토할 후보가 생김"이지 정답 확정이 아니다.
- 그래프에 "승인자 없음"은 **명시 안 됨**이지 승인 불필요가 아니다.
- 2박 24만원에 교육비 30만원을 더하지 않는다. 계산 전에 적용 대상부터 정한다.

## q10 하나로 흐름 따라가기

q10 "교육비 정산 증빙은 무엇인가요?"는 오늘 배운 단계를 전부 거친다.

1. **BM25 (7-1)**: 토큰 불일치로 검색 결과 0개. 자료가 없는 게 아니라 검색 실패다.
2. **평가 (8-2)**: dev 평균 0.9에 숨어 있던 유일한 0점 질문.
3. **Hybrid (8-4)**: 문서 Recall 1.0이 됐지만 수료증 · 영수증 문장(education@60)은 빠질 수 있다.
4. **재검색 (9-2)**: "수강 완료 후 제출" 표현으로 education@60 확보.
5. **Parent 확장 (9-1)**: 원문 전체를 넘겨 증빙 문장까지 Context에 들어간다.

교훈: **문서 ID가 맞아도 답이 든 문장까지 들어왔는지는 본문을 읽어 따로 확인한다.**

## run\_ragas.py 코드에서 배운 점

AI 채점관을 부르되 **비용과 비밀이 새지 않게** 안전장치를 겹겹이 둔 평가 스크립트다.

| 실행 | 하는 일 | 비용 |
| --- | --- | --- |
| 기본 | 로컬 E5 점검(shape \[2, 384\]) + 지표 객체 생성까지만 | 무료 |
| `--execute` | Faithfulness · AnswerRelevancy · ContextRecall · ContextPrecision 실제 채점 | 유료 |
| `--show-recorded` | 2026-10-07 검수 기록 조회 (내 실행 결과 아님) | 무료 |

- `before_request`는 요청 직전 검문소다. 준비 모드 · 허용 주소 · 모델명 · 요청 크기 · 호출 횟수를 검사한다.
- **요청 크기 40,000바이트 · 응답 2048토큰**: `before_request` 안에 하드코딩돼 있다. 2048은 `llm_factory(max_tokens=2048)`과 짝이라 함께 바꿔야 한다.
- **호출 횟수**: `--max-requests` 옵션(기본 20). 범위는 1\~20으로 막혀 있어 20을 넘기려면 `if not 1 <= args.max_requests <= 20` 줄을 고쳐야 한다.
- 지표 하나가 LLM을 여러 번 부르므로 답변 3개 ≠ 요청 3번. 한도를 너무 낮추면 중간에 멈춘다.
- 에러는 종류만 저장(키 노출 방지), `max_retries=0`으로 숨은 재시도 비용 차단.
- `finally`가 실패해도 기록을 남긴다. **`completed: false`면 일부 점수를 완성 결과로 읽지 않는다.**
